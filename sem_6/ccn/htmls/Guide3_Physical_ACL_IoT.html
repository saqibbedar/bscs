OSI Physical Layer

Lectures 13–14 · Media, encoding, signaling, and transmission standards

Role of the Physical Layer

Purpose The Physical Layer creates the electrical, optical, or microwave signal that represents bits in each frame and puts them onto the transmission medium. It defines how raw bits become signals on a wire, fiber, or air.

What the Physical Layer Does

  • Receives frames from the Data Link Layer
  • Converts frames → bits → signals appropriate for the physical medium
  • At receiver, reverses: signals → bits → frames passed up to Data Link Layer
  • Defines: physical/electrical properties of media, mechanical properties of connectors, bit representation by signals (encoding), control information signals
  • Standards set by: IEEE, ANSI, EIA, ITU-T (electrical and communications engineering bodies)

Two Fundamental Principles

Encoding

Converting streams of data into bit patterns. Allows detection of errors and faster speeds. Uses code groups — consecutive sequences of code bits mapped to data bit patterns. Requires start/stop frame bits.

Signaling

Generating the physical signals (electricity, light, radio waves) that represent "1" and "0" on the actual medium. Different media use different signal types.

Basic Encoding Techniques

NRZ — Non Return to Zero

  • Low voltage = 0, High voltage = 1
  • Simple, good for slow-speed data links
  • Very susceptible to interference
  • No self-synchronization

Manchester Encoding

  • Voltage transitions carry the data: low→high = 1, high→low = 0
  • Used in 10BaseT Ethernet
  • Self-clocking — receiver synchronizes from transitions
  • More robust against DC drift

Capacity Terminology

Bandwidth, Throughput, Goodput

Term Definition Key Note
Bandwidth Maximum amount of information that can flow in a given time — theoretical capacity What the link can carry at best
Throughput Actual measure of bits transferred across media over a given time Always ≤ bandwidth; affected by congestion, errors
Goodput Usable data transferred — throughput minus protocol overhead (session setup, ACKs, encapsulation headers) What the application actually gets

Formula: Goodput = Throughput − Overhead (ACKs, session establishment, encapsulation)

Transmission Media

Two Classes of Media Conducted/Guided Media: use a conductor (wire, fiber) to carry signal. Wireless/Un-guided Media: use radio waves; no physical conductor needed.

Copper — Most Common

  • Signal: electrical pulses
  • Main problem: crosstalk — magnetic field from one wire pair interferes with adjacent pairs
  • Solution: twisting wire pairs → cancels crosstalk effect
  • Also affected by EMI, RFI, lightning

Fiber Optic — Most Expensive

  • Signal: patterns of light
  • Main advantage: NO EMI or RFI — immune to electromagnetic noise
  • Use primarily for backbone cabling
  • Thin strands of pure glass; light in weight; unaffected by atmosphere
  • Testing: use OTDR (Optical Time Domain Reflectometer)

Access Control Lists (ACL)

Lecture 15 · Standard, Extended, Named ACLs, Wildcard Masks, Placement

What is an ACL?

Definition An ACL (Access Control List) is a table that tells a router which access rights each user/traffic has to network objects. In Cisco terms: lists of conditions that test network traffic at a router interface and tell the router which packets to accept or deny.

ACL Benefits

  • Limit network traffic and increase network performance
  • Provide traffic flow control
  • Provide a basic level of security for network access
  • Permit or deny hosts from accessing a network segment
  • Make forwarding/blocking decisions at router interfaces
  • Work at Layer 3 — can filter based on IP addresses (and Layer 4 ports for extended)

How ACL Executes

  • ACL statements operate in sequential, logical order — first match wins
  • Packet tested against each statement in order
  • On match: packet is either accepted or rejected based on the statement
  • If no match found → implicit deny all at the end (all unmatched traffic is dropped)
Packet arrives at interface
→
ACL present?
→
Match ACL rule
→
Permit or Deny
→
Forward or Drop

If no ACL exists: packet is encapsulated in new Layer 2 protocol and forwarded normally.

ACL Types and Ranges

Standard ACL (1–99)

  • Filters based on source address only
  • Checks source IP of packets being routed
  • Permits or denies entire protocol suite based on source
  • Placement: close to the destination (because it only looks at source — placing near source would block too broadly)
access-list 1 permit 171.69.2.88
access-list 6 deny 172.13.0.0 0.0.255.255
access-list 6 permit 172.0.0.0 0.255.255.255

Extended ACL (100–199)

  • Filters based on source AND destination address, plus protocol type and port
  • More precise control: where packet originates, destination, TCP/UDP/ICMP, port numbers
  • Can permit/deny specific applications (HTTP, FTP, DNS, etc.)
  • Placement: close to the source (because it can filter precisely — no need to let traffic travel to destination before blocking)

Number ranges: 100–199 and 2000–2699

Standard ACL Commands

Two-step configuration: (1) create the ACL, (2) apply it to an interface.

Step 1 — Create ACL:
Router(config)# access-list [number] {permit|deny} [source] [wildcard]

Step 2 — Apply to interface:
Router(config-if)# ip access-group [number] {in|out}
Delete ACL:
Router(config)# no access-list [number]
(Numbered ACLs cannot be partially altered — must delete and recreate)

Wildcard Masks

Key Rule — Wildcard Mask Logic Wildcard mask bit = 0: CHECK the corresponding IP address bit (must match). Wildcard mask bit = 1: IGNORE (don't check) the corresponding bit. This is the OPPOSITE of subnet masks (subnet: 1=check, 0=ignore).

Common Wildcard Shortcuts

KeywordEquivalentMeaning
host0.0.0.0 maskMatch this exact IP address only
any0.0.0.0 255.255.255.255Match any IP address

Wildcard Examples

  • 172.30.16.0 0.0.0.255 — match any host in 172.30.16.x subnet
  • 172.30.0.0 0.0.255.255 — match any host in 172.30.x.x (entire Class B)
  • 0.0.0.0 255.255.255.255 = any — match everything
  • 172.30.16.5 0.0.0.0 = host 172.30.16.5 — match single host

Named ACLs

Named ACL Advantages

  • Use alphanumeric names to identify ACLs instead of numbers
  • No IOS limit on number of named ACLs
  • Can modify (delete individual entries) without deleting the entire ACL
  • Support additional features: IP options filtering, non-contiguous ports, TCP flag filtering
  • Any additions are made to the end of the ACL
ip access-list standard MY_ACL
 permit 192.168.1.0 0.0.0.255
 deny any

Delete single entry:
 no permit 192.168.1.0 0.0.0.255

ACL Placement Rules — Critical for Exam

Standard ACL → Near Destination

Standard ACL only filters by source. If placed near source, it could block traffic that was meant for a different destination entirely. Place it close to destination to minimize impact.

Extended ACL → Near Source

Extended ACL filters by both source and destination. Placing near source prevents unwanted traffic from crossing the network unnecessarily — blocks it immediately at origin.

ACL and Firewalls

  • A Firewall is an architectural structure protecting the internal network from external intruders
  • ACLs should be used in firewall routers positioned between internal and external networks (e.g., the Internet)
  • Firewall router provides point of isolation — rest of internal network is protected from direct attack

Internet of Things (IoT)

Lecture 16 · IoT definition, architecture, technologies, applications, challenges

What is IoT?

Definition IoT (Internet of Things) comprises physical "things" that have unique identities and are connected to the Internet. The focus is on configuring, controlling, and networking devices traditionally not associated with the Internet — pumps, utility meters, car engines. IoT is a new revolution in endpoint (device) capabilities.

Core IoT Concept

  • Moving from Internet of People → Internet of Things
  • Not just connecting things to the Internet
  • Things communicate and exchange data with each other (M2M — Machine to Machine)
  • Processing this data creates applications for users and machines
  • Scope: devices, appliances, machines, infrastructure

IoT vs M2M

  • M2M (Machine-to-Machine): direct communication between two devices — narrow scope, usually point-to-point
  • IoT: broader ecosystem — devices communicate through cloud platforms, data is processed, analyzed, and used to drive decisions across many systems
  • IoT includes M2M but goes further: analytics, cloud integration, application layer

IoT Architecture

IoT Layered Architecture

Application Layer — Smart Grid, Smart Transport, Green Building, Env. Monitor, Smart Decision
Information Processing Layer — Data Center, Search Engine, Info Security, Data Mining, Cloud
Network Construction Layer — WWAN, WPAN, WMAN, WLAN, Internet, GPS
Sensing & Identification Layer — Smart Devices, RFID, Sensors, Actuators

Bottom layer = physical world sensing. Top layer = intelligent applications driven by that data.

IoT Technologies

Hardware (Devices)

  • Arduino Uno — microcontroller board; very popular for prototyping
  • Raspberry Pi — single-board computer; runs full OS
  • BeagleBone Black — Linux-based embedded board
  • Intel Galileo — Intel x86-based Arduino-compatible board
  • Sensors (temperature, motion, ECG, proximity) and Actuators (motors, relays, LEDs)

IoT Protocols

  • CoAP (Constrained Application Protocol) — lightweight HTTP for resource-constrained devices
  • MQTT (Message Queue Telemetry Transport) — publish-subscribe messaging; used with brokers; very lightweight
  • XMPP (Extensible Messaging and Presence Protocol) — real-time message/data exchange
  • 6LoWPAN — IPv6 over Low-power Wireless Personal Area Networks; IPv6 adapted for constrained devices

IoT Challenges

Four Key Challenges

Connectivity

Heterogeneous (different types, mixed) networks; devices use different protocols, frequencies, and standards. Interoperability is difficult.

Power Management

Many IoT devices are battery-powered; must operate for months or years without replacement. Energy-efficient protocols and sleep modes critical.

Security

Billions of connected devices = massive attack surface. Many IoT devices have no security built in. Authentication, encryption, and update mechanisms needed.

Rapid Evolution

Technologies, standards, and platforms evolve quickly. Legacy devices may become incompatible. Standards fragmentation (multiple competing protocols).

Cloud in IoT — Sensing as a Service IoT data is often sent to cloud platforms (AWS IoT, Azure IoT, Google Cloud IoT) for storage, processing, and analytics. This model is called "Sensing-as-a-Service" — the physical sensing hardware is abstracted into a cloud service layer that applications can subscribe to and consume.
