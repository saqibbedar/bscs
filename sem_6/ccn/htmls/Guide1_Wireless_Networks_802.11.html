Wireless Network Types

Core Distinction Two fundamental modes: Infrastructure Mode (base station connects mobiles to wired network) vs Ad Hoc Mode (no base station — nodes route among themselves).

Infrastructure Mode

  • Wireless hosts associate with a Base Station (BS)
  • Base station connected to wired (larger) network
  • Traditional services provided: addressing, routing (DNS resolution), DHCP
  • Examples: WiFi (802.11) access points, cellular towers
  • Handoff (switching to a different base station): mobile changes base station providing connection to wired network

Ad Hoc Mode

  • No base stations at all
  • Nodes can only transmit to other nodes within link coverage
  • Nodes self-organize and route among themselves
  • No traditional network services — hosts must provide them
  • Similar to peer-to-peer vs client-server model

Why Ad Hoc Networks?

  • Fixed infrastructure not always viable — disaster areas, war zones, emergency rescue
  • Short-range radios make infrastructure impractical (Bluetooth range ≈ 10m)
  • Easy and fast to deploy; no backbone support needed
  • Cellular vs Ad Hoc: cellular = centralized routing, guaranteed bandwidth, circuit-switched; ad hoc = distributed routing, shared channel, packet-switched, frequent path breaks

802.11 LAN Architecture

Key Components

  • Access Point (AP) — the base station for 802.11; communicates with wireless hosts
  • BSS (Basic Service Set) — coverage area of one AP; AP acts as master
  • SSID (Service Set Identifier) — the "network name" identifying a BSS
  • Multiple BSSs connect through a hub/switch/router to the Internet

Association Process

  • AP admin chooses a frequency channel for the AP
  • APs send periodic beacon frames containing SSID + MAC address
  • Host scans channels, hears beacons, selects AP to associate with
  • Then may perform authentication + DHCP to get an IP

802.11 Protocol Stack (MAC Layer)

  • DCF — Distributed Coordination Function: medium access is contended by all stations. Uses CSMA/CA + RTS/CTS to reduce collisions. Default mode.
  • PCF — Point Coordination Function: AP (point coordinator) controls access. Stations transmit after a shorter interval. Deterministic, contention-free.

Remember: 802.11 uses CSMA/CA (Collision Avoidance) — not CSMA/CD (Collision Detection) like wired Ethernet.

Wireless Link Challenges

Why Wireless is Hard Unlike wired links where most loss = congestion, wireless has inherently higher bit-error rates due to signal physics. This fundamentally changes how protocols must work.

Cause 1: Signal Attenuation

  • Signal disperses as it travels greater distance
  • Attenuates (weakens) as it passes through matter
  • Result: bit errors at receiver increase with distance

Cause 2: Interference

  • Other radio sources in the same frequency band
  • Example: 2.4 GHz cordless phones interfere with 802.11b
  • Microwave ovens, fluorescent lights cause electromagnetic noise

Cause 3: Multipath Propagation

  • Electromagnetic waves reflect off buildings, furniture, people
  • Signal takes many paths of different lengths to reach receiver
  • Multiple copies arrive at receiver with different delays → signal blurring

Dealing with Bit Errors

  • Increase transmission power → bad for battery, causes more interference
  • Stronger error detection codes (more powerful CRC)
  • Link-layer retransmission of corrupted frames (ACK-based)
  • 802.11 uses both: CRC check + ACK + retransmit on failure

MAC Problems: Hidden & Exposed Terminal

Why CSMA/CD Fails Wirelessly In wired Ethernet, a station listens while it transmits to detect collisions. Wirelessly, signal strength received is far weaker than sent — you can't hear your own collision. Also, two stations may be unaware of each other but both interfere at a third node.

Hidden Terminal Problem

  • A sends to B. C cannot detect A's transmission (out of range)
  • C senses medium = idle (Carrier Sense fails for C)
  • C starts transmitting → collision at B
  • A cannot detect the collision (CD fails)
  • A is "hidden" from C
A ——— B ——— C
A and C in range of B but not each other

Exposed Terminal Problem

  • B sends to A. C wants to send to D
  • C senses carrier (B's transmission) — finds medium busy, waits
  • But A is outside C's radio range — C waiting is unnecessary!
  • C could safely transmit to D without interfering with A
  • C is "exposed" to B's transmission unnecessarily
A ←— B   C ——→ D
C can transmit to D but wrongly waits due to sensing B
Exam Summary Hidden terminal = CS fails (node can't detect ongoing transmission) → collision at receiver.
Exposed terminal = node waits unnecessarily → wasted throughput.

MACA — The Solution

MACA: Multiple Access with Collision Avoidance

Uses short signaling packets before actual data transmission. Variants of this method are used in IEEE 802.11.

RTS — Request to Send

Sender sends a short RTS packet to receiver before sending data. Contains: sender address, receiver address, duration of intended transmission.

CTS — Clear to Send

Receiver replies with CTS when ready to receive. All nodes that hear CTS know to stay silent for the duration.

Solves Hidden Terminal

  • A and C both want to send to B
  • A sends RTS first → B replies CTS
  • C hears B's CTS → knows B is busy → C waits
  • Collision avoided even though C can't hear A

Solves Exposed Terminal

  • B sends to A, C wants to send to D
  • C hears B's RTS but does NOT receive A's CTS (out of range)
  • Since C doesn't hear CTS, C knows its target isn't being used
  • C proceeds to transmit to D — no unnecessary waiting

CSMA/CA — How 802.11 Actually Works

  • Once a station starts transmitting, it needs aggressive collision avoidance
  • After sensing an idle channel, stations wait an additional random backoff time before transmitting (reduces two stations starting at same moment)
  • Receiving station sends ACK if packet received correctly
  • Sender retransmits if no ACK received within timeout
  • Gives up after multiple failed retransmissions
  • CRC used to detect bit errors in the frame

Host Mobility

Three Degrees of User Mobility

ScenarioWhat HappensChallenge
Moves within same access networkIP address stays same; ongoing transfers continueMinimal — only link-layer changes
Shuts down between movesGets new IP address at new networkLow — no ongoing transfers to maintain
Moves while active (true mobility)Must maintain ongoing connections while changing networksHard — need to ensure traffic keeps reaching host

Mobility Within Same Subnet

  • H1 keeps same IP address — ongoing transfers uninterrupted
  • H1 detects weakening signal from current AP → scans for stronger one
  • Changes to another AP with same SSID
  • Disassociates from old AP, associates with new AP
  • Switch learns new location via self-learning mechanism
The Core Mobility Problem "Wireless breaks the abstraction of a link. Mobility breaks the association of address and location." TCP treats packet loss as congestion; mobile wireless causes non-congestion loss. TCP also doesn't handle changing RTT (Round-Trip Time) well. Higher-layer protocols don't perform as expected.

Mobile IP — Maintaining Connections Across Networks

Key Terminology

TermDefinition
Home NetworkMobile's permanent home network (e.g., 128.119.40/24)

Indirect Routing (Triangle Routing)

1

Correspondent sends to mobile's permanent address

2

Home agent intercepts, tunnels to foreign agent

3

Foreign agent forwards to mobile

4

Mobile replies directly to correspondent

Location is transparent to correspondent. But creates triangle routing inefficiency — packet goes home network even if correspondent and mobile are nearby.

Direct Routing

1

Correspondent asks home agent for mobile's COA

2

Correspondent sends directly to foreign agent

3

Foreign agent forwards to mobile

4

Mobile replies directly to correspondent

No longer transparent to correspondent — it now knows mobile's location directly.

Home agent now knows COA

Letting Routing Protocol Handle Mobility (Alternative)

  • Mobile node injects its address into routing protocol (e.g., OSPF)
  • Advantage: no changes to end host; efficient routing path
  • Disadvantage: does not scale — too many routing messages, bigger routing tables
  • Example: Boeing Connexion (WiFi at 35,000 feet) used BGP with IP block per airplane
Exam Trick — Indirect vs Direct Routing Indirect = triangle inefficiency but location transparent to correspondent.
Direct = efficient routing but correspondent must know mobile's COA.
Mobile always replies directly in both cases — only the correspondent-to-mobile path differs.
