— LAYER 02 — The Data Link Layer

The layer that takes raw bits from Layer 1 and turns them into structured frames, handling node-to-node (hop-to-hop) delivery on a single physical link.

Real-world analogy If the Physical Layer is the motorcycle that moves an envelope between two post boxes, the Data Link Layer is the local postal worker at each post box — he writes the next post box's address on the envelope (MAC), wraps the letter in a labelled package (framing), checks that the package isn't damaged (error control), waits his turn to hand it over (access control), and throttles delivery if the next office is overwhelmed (flow control). Crucially, he only cares about the next hop, not the final recipient.

§ 01 Core Responsibilities

From the slide "Duties of Data Link Layer" (Lec 2, Slide 30), five responsibilities are explicit:

  • Framing The Data Link Layer groups incoming bits from Layer 1 into discrete, structured units called frames. A frame has a defined start, end, header, payload, and trailer. Framing turns a formless bit stream into something that can be individually addressed, error-checked, and acknowledged.
  • Physical Addressing (MAC) Every frame carries a source and destination MAC address — a 48-bit, globally unique hardware address burned into the network interface. These addresses identify the sender and next-hop receiver on the same physical network. MAC addresses are not routed; they only matter within a single link.
  • Flow Control Prevents a fast sender from overwhelming a slow receiver on the same link. If the receiver's buffer fills up, Data Link Layer protocols use flow-control techniques (stop-and-wait, sliding window at L2) to signal the sender to pause or slow down.
  • Error Control Detects — and in some protocols corrects — bit errors that occur during physical transmission. Done using a checksum or CRC placed in the frame trailer. On detection, the frame is either discarded (most common) or retransmitted via ARQ protocols.
  • Access Control When multiple devices share the same medium (e.g., Wi-Fi, or a bus cable), the Data Link Layer decides who gets to transmit when. Mechanisms include CSMA/CD (Ethernet), CSMA/CA (Wi-Fi), and token passing.

The slide separately emphasises the Data Link Layer is responsible for "hop-to-hop delivery" (also called node-to-node) — this phrase must appear in your answer.

§ 02 Detailed Concepts

2.1 What "Hop-to-Hop" really means

A packet travelling from a PC in Islamabad to a server in Frankfurt passes through many routers. Each link between adjacent routers is one "hop." The Data Link Layer only operates on a single hop — when the frame reaches the next router, the frame is torn apart, the packet inside is routed, and a new frame is built for the next hop. The Network Layer (L3) worries about the end-to-end journey; L2 only worries about "how do I get this packet to the next device on this wire."

2.2 The MAC Address

  • 48 bits, written as six hex bytes: 00:1A:2B:3C:4D:5E.
  • First 24 bits = OUI (Organisationally Unique Identifier, IEEE-assigned to the vendor).
  • Last 24 bits = NIC-specific serial number chosen by the vendor.
  • Burned into the network interface card at manufacturing time. (Can be overridden in software on modern systems.)
  • Used only within a single broadcast domain / LAN. Routers rewrite the MAC address at every hop.

2.3 Framing — giving structure to bits

A generic Ethernet-style frame looks like this:

PreambleBit sync
Dest MAC48 bits
Src MAC │ Type │ Data / PayloadUpper-layer packet lives here
FCS / CRCError check
EndFrame gap

The framing must solve two subtle problems: (1) how does the receiver know where a frame starts and ends? (2) what if the end-of-frame marker accidentally appears inside the data? The answer is techniques like byte stuffing, bit stuffing, or length counting in the header — not examined in depth in these slides, but worth naming.

2.4 Flow Control

The same "fast sender, slow receiver" problem occurs at Layer 4 too — but at Layer 2 it is solved between adjacent nodes, not end-to-end. Two classical techniques:

  • Stop-and-Wait — send one frame, wait for ACK, send the next. Simple; poor throughput on links with high bandwidth-delay product.
  • Sliding Window (at L2) — send up to N unacknowledged frames before pausing. N is the window size.

2.5 Error Control

Noise on the physical medium flips bits. The Data Link Layer:

  1. Computes a checksum or CRC over the frame's contents.
  2. Appends the result in the frame's trailer.
  3. On receipt, recomputes the checksum. If it doesn't match, the frame is corrupt.

Corrupt frames are typically silently discarded. Recovery is left to higher layers (TCP at L4, for example). Some L2 protocols do retransmit (ARQ), but Ethernet itself does not — it relies on TCP.

2.6 Access Control — sharing the medium

Required only when the medium is shared. The slides mention it as a duty but the techniques themselves are:

  • CSMA/CD (Carrier Sense Multiple Access with Collision Detection) — classical Ethernet. Listen → if idle, transmit → if collision detected, abort and retry after a random back-off.
  • CSMA/CA (Collision Avoidance) — Wi-Fi. Can't detect collisions mid-air, so avoids them using RTS/CTS handshakes and random back-off before transmit.
  • Token Passing — a special control frame (the "token") circulates; only the holder may transmit. Used in Token Ring, FDDI.

2.7 Two sub-layers (useful context)

IEEE formally splits the Data Link Layer into two:

LLC — Logical Link Control

Upper sublayer. Provides a uniform interface to the Network Layer regardless of physical technology. Handles flow and error control, multiplexes Network Layer protocols.

MAC — Media Access Control

Lower sublayer. Handles physical addressing, access to the shared medium, framing at the hardware level. This is where MAC addresses come from.

HOP-TO-HOP DELIVERY — Data Link Layer's scope Host A ──── [Hop 1] ──── Router R1 ──── [Hop 2] ──── Router R2 ──── [Hop 3] ──── Host B │ │ │ frame F1 frame F2 frame F3 (new MACs for H1) (new MACs for H2) (new MACs for H3) The IP packet INSIDE survives unchanged from A to B. The L2 FRAME is rebuilt on every hop with new source/destination MAC.
Fig. 2.1 — Data Link operates per-hop. The frame is short-lived; the packet is end-to-end.
Step-by-step. (1) Host A builds a frame with src MAC = A, dst MAC = R1, and sends it on Hop 1. (2) R1 receives the frame, strips the L2 header, looks at the L3 (IP) destination, decides the next hop is R2. (3) R1 builds a new frame with src MAC = R1, dst MAC = R2, and sends it on Hop 2. (4) The process repeats until the frame arrives at Host B. Inside all these frames, the original IP packet is carried untouched.
What the examiner wants you to see The MAC address changes at every hop. The IP address does not. If you write that the destination MAC is the same from A to B, that is wrong and costs the full mark.

Diagram 3.2 — The Data Link Layer Example (Slide: Lec 2, Slide 32)

Host A wants to send to Host F through one LAN: ┌────────────────── Shared LAN segment ───────────────────┐ │ │ │ │ A(MAC_a) B(MAC_b) C(MAC_c) F(MAC_f) A sends a frame with: Source MAC = MAC_a Destination MAC = MAC_f Payload = [ IP packet, TCP segment, app data... ] Trailer = CRC/FCS Every NIC on the LAN sees the frame, but only F's NIC accepts it because the destination MAC matches F's burned-in address.
Fig. 2.2 — Frames on a shared LAN: physical addressing enables selective delivery.
Step-by-step. On a shared medium (hub or legacy Ethernet), every NIC receives every frame. Each NIC checks the destination MAC. If it does not match, the NIC discards the frame silently. If it matches (or if the address is the broadcast FF:FF:FF:FF:FF:FF), the NIC accepts the frame and hands it up to Layer 3.
What the examiner wants you to see Physical addressing = hardware filtering. Selective acceptance by MAC is the mechanism that makes Layer 2 efficient on a shared medium.

§ 05 Data Handling

At Layer 2 the PDU is the FRAME.

Encapsulation role

The Data Link Layer takes a packet from Layer 3, adds its own header (destination MAC, source MAC, type) at the front and a trailer (CRC/FCS) at the end — producing a frame. The frame is handed down to Layer 1 as a bit stream. On receipt, the process is reversed: the bit stream is reassembled into a frame, the header and trailer are verified and stripped, and the packet is handed up to Layer 3.

ENCAPSULATION AT LAYER 2 Layer 3 hands down: [ IP header │ data ] ← PACKET Layer 2 wraps it: ┌───────────┬────────────────────────────┬──────┐ │ L2 header │ [ IP header │ data ] │ FCS │ ← FRAME └───────────┴────────────────────────────┴──────┘ ▲ ▲ Dst MAC, Src MAC, Error-check Length/Type (CRC) Handed down to Layer 1 as bits.

Headers & Trailers

The slides explicitly ask: "What are headers and trailers, and how do they get added and removed?" Answer template: headers are added on the sending side at each layer during encapsulation; trailers (mostly L2's FCS and some L7 protocols) are added at the end of the frame. On the receiving side, each layer decapsulates by reading and stripping its own header/trailer before passing the inner PDU upward.

§ 06 Must-Remember Points

High-Priority Facts

  • PDU = FRAME. Layer 2 groups bits into frames.
  • Delivery model = HOP-TO-HOP / NODE-TO-NODE. Always include this exact phrase.
  • Five duties: Framing, Physical addressing (MAC), Flow control, Error control, Access control.
  • Device examples: switch, bridge, NIC, access point.
  • MAC is 48 bits, OUI + vendor portion, burned into the NIC.
  • Two sublayers (bonus): LLC (upper), MAC (lower).
  • CSMA/CD for wired Ethernet; CSMA/CA for Wi-Fi.

Common Exam Traps

Trap 1: Saying Layer 2 handles "end-to-end" delivery. No — that is Layer 3 (host-to-host) or Layer 4 (process-to-process). L2 is only per-hop.
Trap 2: Listing IP as a Layer 2 protocol. IP is Layer 3. Ethernet is Layer 2.
Trap 3: Forgetting that MAC addresses change at every router. Examiners love to ask what changes and what stays the same from source to destination.
Trap 4: Confusing a hub (Layer 1) with a switch (Layer 2). A hub just regenerates bits; a switch reads the MAC and forwards selectively.
Trap 5: Confusing Layer 2 flow control with Layer 4 (TCP) flow control. L2 = between adjacent nodes. L4 = end-to-end.

Memory Shortcuts

  • FAM-FEA: Framing, Addressing (MAC), Media access, Flow control, Error control, Access control — the mnemonic for the five duties (with framing + addressing at the top).
  • "Hop-to-hop, Frame on the way, MAC for the next bay."
  • PDU ladder: Bits → Frames → Packets → Segments → Data. Frames = L2.

§ 08 Critical Questions

Conceptual

  1. State the five duties of the Data Link Layer as given in the slides.
  2. Explain what "hop-to-hop" or "node-to-node" delivery means. How does it differ from "source-to-destination" delivery?
  3. What is a MAC address? How long is it, and how is it structured?
  4. Distinguish between the LLC and MAC sublayers of Layer 2.
  5. Why does the Data Link Layer need access control? Under what conditions does it not need it?

Short-Answer

  1. Name three Layer 2 devices.
  2. What is framing and why is it necessary?
  3. Give one protocol that uses CSMA/CD and one that uses CSMA/CA.
  4. What is the difference between Layer 2 flow control and Layer 4 flow control?
  5. What is placed in the frame trailer, and what is it used for?

Diagram-Based

  1. Draw the encapsulation of a packet into a frame, labelling the header, payload, and trailer.
  2. Draw a packet travelling from Host A to Host B via two routers R1 and R2. At each hop, show the source and destination MAC addresses and the source and destination IP addresses. Highlight what changes and what stays the same.
  3. Draw a shared LAN with five devices. Illustrate frame acceptance when A sends to E — which devices see the frame, and which accepts it?

Scenario-Based

  1. A user reports that on a 100 Mbps Ethernet LAN, collisions occur frequently. Which layer's mechanism handles this, and what is that mechanism called?
  2. A file transfer from a server to a thin client succeeds over Wi-Fi but fails when the Wi-Fi signal weakens. TCP retransmits the lost packets. Identify which layer first detected the corruption (bit errors) and which layer recovered the data.
  3. You tap into a switched LAN and capture a frame. You observe that the destination MAC address is FF:FF:FF:FF:FF:FF. What does this mean, and how will switches handle this frame?
  4. A company's network team replaces all its hubs with switches. Explain which OSI layer the two devices operate at, and name one specific performance benefit of the change.
