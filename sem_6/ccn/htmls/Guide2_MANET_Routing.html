What is a MANET?

Definition MANET (Mobile Ad Hoc Network) — a network formed by wireless, potentially mobile hosts without any pre-existing infrastructure. Routes may contain multiple hops. Nodes move, so routes change dynamically.

Key Properties

  • Formed by wireless hosts that may be mobile
  • No pre-existing infrastructure required
  • Routes between nodes may need multiple hops
  • Mobility causes route changes → protocols must adapt
  • Nodes must themselves perform routing/switching

Why MANET?

  • Ease of deployment — no infrastructure setup
  • Speed of deployment — operational immediately
  • Decreased infrastructure dependence
  • Used in: battlefields, emergency rescue, disaster areas, collaborative computing, vehicular networks (VANET)

MANET Challenges

ChallengeWhat It Means
Limited wireless rangeCannot reach distant nodes directly — needs multi-hop routing
Broadcast mediumAll transmissions are heard by all nearby nodes — hidden terminal problem persists

MANET Variations

  • Fully Symmetric: all nodes have identical capabilities and responsibilities
  • Asymmetric Capabilities: different transmission ranges, battery life, processing power, movement speeds at different nodes
  • Asymmetric Responsibilities: only some nodes route packets; some act as cluster heads (leaders of nearby nodes)
  • Traffic can be: unicast / multicast / geocast (geographic) / broadcast / anycast
  • May co-exist with infrastructure networks

Routing Protocol Classification

Proactive Protocols

  • Determine routes independent of traffic — routes are always maintained
  • Traditional link-state and distance-vector protocols are proactive
  • Lower latency for route discovery — routes already known
  • Higher overhead — continuous route updating even when no traffic

Reactive Protocols

  • Maintain routes only when needed — on-demand
  • Route from X to Y found only when X tries to send to Y
  • Higher latency — must discover route before sending
  • Lower overhead — routes only discovered when needed
  • Example: DSR (Dynamic Source Routing), AODV

Hybrid Protocols

Combine proactive and reactive strategies — proactive within a zone (for nearby nodes), reactive beyond that zone. Better trade-off depending on network size and mobility.

Trade-Off Summary Which is better — proactive or reactive — depends on traffic patterns and node mobility. High mobility + infrequent traffic → reactive better (routes would go stale anyway). Low mobility + frequent traffic → proactive better (route discovery overhead amortized over many packets).

Flooding for Data Delivery

How Flooding Works

  • Sender S broadcasts data packet P to all neighbors
  • Each node receiving P for the first time forwards P to its neighbors
  • Sequence numbers prevent forwarding the same packet more than once
  • Packet reaches destination D if D is reachable from S
  • Node D does not forward the packet (it's the destination)
  • Nodes unreachable from S do not receive P

Advantages of Flooding

  • Simplicity — no routing table maintenance needed
  • More efficient than discovery protocols when data rate is very low (overhead of discovery is higher than just flooding)
  • Potentially higher reliability — packet may arrive via multiple paths

Disadvantages of Flooding

  • Very high overhead — packet may be delivered to too many unnecessary nodes
  • Hard to implement reliable broadcast without increasing overhead
  • Hidden terminal collisions: if J and K both try to forward to D simultaneously, and J and K can't hear each other → collision → packet lost at D
  • In worst case, all reachable nodes receive the packet
Flooding of Control Packets Many MANET protocols flood control packets (not data packets) to discover routes, then use the discovered route to send actual data. The flooding overhead is amortized (spread out) over the data packets sent between route discoveries. This is the basis for DSR.

DSR — Dynamic Source Routing

Core Idea of DSR When node S wants to send to D but doesn't know a route, S floods a Route Request (RREQ). Each forwarding node appends its own ID. When RREQ reaches D, D sends a Route Reply (RREP) back along the reverse path. S then caches the full route and includes it in every data packet header — hence "source routing."

Phase 1: Route Discovery

  • S floods RREQ (Route Request) to all neighbors
  • Each intermediate node appends its own identifier to the RREQ before forwarding
  • A node that has already forwarded this RREQ does NOT forward it again (uses sequence numbers)
  • Hidden terminal issue: if two nodes simultaneously forward RREQ to D, collision may prevent D from receiving it

Phase 2: Route Reply

  • Destination D receives RREQ and sends RREP (Route Reply)
  • D sends RREP back by reversing the route in the received RREQ
  • RREP includes the complete route from S to D
  • Condition: link reversal only works if links are guaranteed to be bi-directional
  • If unidirectional links exist, D must initiate its own route discovery back to S, and piggybacking RREP on that RREQ
  • IEEE 802.11 MAC requires bi-directional links (ACK used) — so reverse route is valid in 802.11

Phase 3: Data Delivery

  • S caches the route learned from RREP
  • When S sends data to D, the entire route is included in the packet header
  • Intermediate nodes read the source route in the header to know where to forward next
  • No routing table at intermediate nodes — the source carries the full path
  • Downside: packet header size grows with route length (long routes → large headers)

DSR Optimizations: Route Caching

What Gets Cached

Nodes cache new routes learned by any means — not just from their own route discoveries.

EventWhat Node Learns
S finds route [S,E,F,J,D] to DS also learns [S,E,F] to F, [S,E] to E
K receives RREQ [S,C,G] for DK learns [K,G,C,S] — reverse path to S
F forwards RREP [S,E,F,J,D]F learns [F,J,D] to D
E forwards DATA [S,E,F,J,D]E learns [E,F,J,D] to D
Node overhears a data packetLearns partial route from packet header

How Cache Speeds Up Discovery

  • When S finds route to D is broken → checks local cache first
  • If alternate route to D in cache → uses it immediately, no new RREQ needed
  • When node X receives an RREQ for D → if X knows a route to D in cache → X can send RREP itself without flooding reaching D
  • Can speed up route discovery significantly
  • Can reduce propagation of RREQs through network

Cache Format

  • DSR maintains cached routes in a tree format at each node
  • The tree root is the local node
  • Branches represent different cached paths to different destinations
  • Stale (outdated) cached routes can cause problems when topology changes — must be handled carefully

Routing Types in MANET

Types of Routing in Ad Hoc Networks

TypeDefinitionExample Use
Unicast One sender → one specific receiver. Standard point-to-point communication. DSR, AODV, DSDV. Most common MANET routing type.
Multicast One sender → a group of receivers simultaneously Video streaming to group of nodes; military broadcasts
Geocast (Geographic) Packets delivered to all nodes within a specific geographic region Location-aware applications; VANET warning alerts
Broadcast Packets delivered to all nodes in the network Network-wide control messages, route requests (flooding)
Anycast Packet delivered to any one node from a group (nearest/best available) Querying nearest server or service provider
DSR is a Unicast Reactive Protocol DSR falls under: Unicast (one sender, one receiver) + Reactive (route discovered on-demand) + Source Routing (full route in packet header) + Route Caching (learns routes opportunistically from overheard packets).

Performance Criteria in MANET Routing

  • Throughput: total data successfully delivered
  • Latency: delay from sender to receiver (route discovery adds latency in reactive protocols)
  • Route stability: how long a discovered route stays valid despite mobility
  • Energy consumption: important for battery-powered nodes
  • Overhead: control packet cost relative to data delivered
  • Scalability: does performance degrade with more nodes?
  • No single protocol performs best in all environments — research focuses on adaptive protocols
