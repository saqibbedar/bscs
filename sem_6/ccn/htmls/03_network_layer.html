Network Layer

The layer
that finds
the way.

Source-to-destination delivery of packets across multiple networks — logical addressing, routing, and internetworking.

Real-world analogy

Think of the postal system at the inter-city level. Layer 2 (Data Link) is the local postman who carries mail between two nearby houses on one street. Layer 3 (Network) is the sorting hub that decides: "This letter from Islamabad is addressed to Lahore — route it via Rawalpindi, then Jhelum, then Gujranwala." The Network Layer doesn't carry the letter itself; it decides which path the letter takes across the entire postal network, hop by hop, until the destination city is reached.

§ 02 Core Responsibilities

The three duties Dr. Khan's Slide 34 pins to this layer, expanded.

  • Logical Addressing IP Data Link addressing (MAC) only works within a single physical network — it cannot identify a host that lives on the other side of a router. The Network Layer adds a logical address (the IP address) to every packet in the header. This logical address is hierarchical and globally meaningful, so a packet can be routed across any number of intermediate networks and still find its destination.
  • Internetworking L3 superpower The Network Layer is what makes "the Internet" possible. It connects together networks that may use completely different Layer-1 / Layer-2 technologies (Ethernet LAN, Wi-Fi, fibre backbone, cellular) and presents them to the upper layers as a single, uniform logical network. The packet stays the same; only the Layer-2 frame changes at every hop.
  • Routing path selection When multiple paths exist between source and destination, routers at the Network Layer choose which path a packet takes. Routing is done using routing tables, which are built either manually (static routes) or automatically by routing protocols (RIP, EIGRP, OSPF, BGP). At each router, the packet is forwarded one hop closer to its final destination — this process is called next-hop forwarding.

Quick compare. Data Link says "deliver this frame to the next node on this wire." Network says "deliver this packet to that host, wherever it is in the world." Transport says "deliver this data to that specific process on that host." All three say "delivery" — but across different scopes.

§ 03 Detailed Concepts

Every idea Lec 5 touches on, expanded with the depth a slide-deck bullet cannot give you.

3.1 · Role of the Network Layer

The Network Layer describes communication from one end device to another end device, regardless of the number of intermediate networks between them.

End devices (hosts) are where data originates and terminates. Between any two end devices sit zero, one, or many intermediary devices (routers). The Network Layer's contract with the Transport Layer above is simple: "Hand me a segment, give me a destination IP, and I will deliver it — I do not promise how or guarantee that it will arrive, but I will try my best to route it there."

This is why IP is described as a best-effort, connectionless, unreliable, media-independent protocol. Each of those four words is loaded — Dr. Khan dedicates a separate slide to each (Lec 5 Slides 4–7), and they are explained individually below.

3.2 · IPv4 — the basic characteristics

Connectionless

No connection is established before sending a packet; no handshake; no state kept about the destination.

Each IP packet is treated as an independent entity. The source does not call the destination first to say "I'm about to send 1,000 bytes, get ready." It simply drops the packet onto the network and hopes it arrives. This is the opposite of TCP, which is connection-oriented and does a 3-way handshake first.

Implication for the student: two consecutive packets from the same source to the same destination may take completely different routes, arrive out of order, or one may arrive while the other is lost. IP does not care. If order and reliability matter, that's TCP's job — not IP's.

Best-effort (unreliable)

IP does not guarantee that a packet will be delivered. It does not retransmit lost packets, it does not acknowledge received packets, and it does not detect duplicates.

"Best effort" does not mean "careless" — it means the Network Layer will do its reasonable best to forward the packet, but it offers no delivery guarantee. If a router's queue is full, the packet is dropped silently. If a link goes down mid-transit, the packet is discarded. Reliability, if needed, must be added by a higher layer (TCP).

Common exam confusion: "unreliable" is a technical term, not a value judgement. It means "no delivery guarantees." IP is unreliable by design — to keep it fast, simple, and scalable to billions of hosts. Reliability costs overhead; IP pushes that cost up to whoever needs it.

Media-independent

The Network Layer does not care what physical medium the packet traverses. Ethernet cable, fibre optic, Wi-Fi, satellite, cellular — all look identical to IP.

This is the single most important engineering decision in the design of the Internet. Because IP is media-independent, a packet from your laptop (Wi-Fi) can cross an undersea fibre cable, a satellite link, a corporate Ethernet LAN, and a 5G radio tower on its way to a server — and the packet itself is identical at every step. Only the Layer-2 encapsulation changes (the frame is rebuilt at every hop), never the Layer-3 packet.

There is one Layer-3-level concession to media diversity: the MTU (Maximum Transmission Unit) of different media varies (Ethernet = 1500 bytes, classic PPP = 1500, older serial = 576). When a packet is too large for the next hop's MTU, the Network Layer can perform fragmentation — splitting a large packet into smaller ones that fit, and letting the destination reassemble them.

3.3 · Encapsulation: segment → packet

Above the Network Layer, the Transport Layer produces segments (TCP) or datagrams (UDP). The Network Layer takes the segment, prepends its own header (source IP, destination IP, TTL, protocol number, etc.), and the result is called a packet. That packet is then handed down to Layer 2, which prepends its own header and trailer and hands the result (a frame) to Layer 1.

At the destination host, the process runs in reverse: Layer 2 strips off its frame header/trailer and hands a packet up to Layer 3; Layer 3 strips off the IP header and hands a segment up to Layer 4; and so on. This is called decapsulation.

At every router along the way, the Layer-2 frame is discarded and rebuilt for the next hop, but the Layer-3 packet is preserved unchanged (except TTL is decremented, and checksum is recomputed).

3.5 · Grouping devices into networks — and why

Lec 5 Slides 11–16 spend six slides on the same underlying question: why don't we just put every device in the world on one flat network? The answers, organised:

(a) Performance

A single flat network is a shared medium (or behaves like one). Every broadcast from any host reaches every other host. With thousands of devices, the bandwidth consumed by broadcasts alone would saturate the network. Dividing into smaller networks contains broadcast traffic — each subnet is its own broadcast domain, and routers do not forward Layer-2 broadcasts between them.

(b) Security

On a flat network, every host can see every other host's traffic. Dividing devices into subnets lets administrators place firewall / ACL rules at the boundary routers, blocking traffic between subnets unless explicitly allowed. A compromised device in the guest-Wi-Fi subnet cannot automatically reach hosts in the server subnet.

(c) Addressing scale

A flat addressing scheme (think: every phone in the world with a random 10-digit number) makes routing tables unmanageably huge. Hierarchical addressing — country code, city code, subscriber number — makes routing tractable. IP addressing does the same: the network portion (prefix) tells routers which network a host is on; the host portion identifies the specific device within that network. Routers only need to know the paths to networks, not to individual hosts.

(d) Containment of failures

A routing loop, broadcast storm, or misconfigured host in a subnet stays within that subnet. Without hierarchical division, a single fault can take down an entire organisation.

3.6 · Hierarchical addressing

An address that encodes where the host is, not just who it is.

An IPv4 address is 32 bits, conventionally written as four dotted decimal octets, e.g. 192.168.10.25. The address is split into two parts by a subnet mask:

  • Network portion — identifies the network. All hosts in the same network share the same network portion.
  • Host portion — identifies the specific device within that network.

This is exactly analogous to a postal address: "25, Street 10, Sector F-7, Islamabad." A router far away doesn't care about Street 10 or house 25 — it only cares about getting the letter to Islamabad. Once in Islamabad, a local router cares about Sector F-7. Once in F-7, the local postman cares about Street 10, house 25. Each layer of the hierarchy is handled by the router at the appropriate scope. Hierarchical addressing is what makes routing tables small enough to be usable.

3.7 · Routes, next-hop, and packet forwarding

Lec 5 Slides 17–25 are entirely about this — it is the largest single concept block in the lecture.

What is a route?

A route is an entry in a router's routing table. Dr. Khan's slide 20 says a route has three key parts:

  1. Destination network — the network we are trying to reach (expressed as a prefix, e.g. 10.1.2.0/24).
  2. Next-hop address — the IP address of the adjacent router to which this router should forward the packet in order to get it closer to the destination. The router does not know the entire path; it only knows "the next guy."
  3. Outgoing interface — the local interface (e.g. GigabitEthernet0/1) through which the packet must leave this router to reach the next hop.

What is a gateway?

A gateway is the intermediary device (a router) that allows devices to communicate across sub-divided networks. When your laptop wants to reach a server on a different subnet, it sends the packet to its "default gateway" — a router whose job is to look at the destination IP, consult its routing table, and forward the packet onward. The gateway is the bridge between networks.

Packet forwarding — the core decision loop

When a packet arrives at a router, the router:

  1. Strips the Layer-2 frame (discards source/dest MAC — they were for the previous hop only).
  2. Decrements the TTL by 1. If TTL is now 0, drops the packet and sends an ICMP "Time Exceeded" message back to the source (this is how traceroute works).
  3. Looks up the destination IP address in the routing table using longest prefix match.
  4. Finds the next-hop IP and outgoing interface.
  5. Recomputes the IP header checksum (because TTL changed).
  6. Builds a new Layer-2 frame for the outgoing interface, with source MAC = router's own MAC, destination MAC = next-hop router's MAC (found via ARP).
  7. Transmits the frame out the chosen interface.

The crucial insight: the IP packet is unchanged from source to destination (except TTL and checksum). The Layer-2 frame is rebuilt at every hop.

3.9 · Routing protocols — preview

Lec 5 only mentions routing protocols in passing; Lec 6 is where they are explored. For Layer-3 completeness, the essentials:

  • Distance Vector (RIP, IGRP, EIGRP) — each router knows only the distance (hop count or metric) and the vector (direction) to each destination. Periodic updates to neighbours. Simple, but slow to converge.
  • Link State (OSPF, IS-IS) — each router floods the entire network with information about its own links; every router independently builds a complete map and runs Dijkstra's shortest-path algorithm. Faster convergence, more CPU/memory.
  • Path Vector (BGP) — used between autonomous systems (Internet backbone). Carries full AS-path to prevent loops.

§ 04 Subnetting — the full treatment

Not explicitly in the slides — but essential to the Network Layer and frequently examined. Theory → mask arithmetic → worked examples → VLSM.

Note · Lec 5's slide 16 says "describe the purpose of further subdividing networks into smaller networks" but the slide itself has no content. Below is the standard Cisco CCNA treatment of subnetting to fill the gap, since you explicitly asked for it.

4.1 · Why subnetting exists

Classful IP addressing (A, B, C) was the original scheme:

ClassFirst octetDefault maskNetworksHosts / net
A1 – 126/8 (255.0.0.0)12616,777,214
B128 – 191/16 (255.255.0.0)16,38465,534
C192 – 223/24 (255.255.255.0)2,097,152254
D224 – 239Multicast (no mask)
E240 – 255Experimental / reserved

The problem: a company with 500 hosts cannot fit in a Class C (254 hosts) but wastes 65,034 addresses if given a Class B. Solution: subnetting — borrow bits from the host portion to create more (smaller) networks from a single classful block. This is the origin of CIDR (Classless Inter-Domain Routing), where the mask is written as a prefix length (e.g. /23) and is not tied to class boundaries.

4.2 · The subnet mask

A 32-bit mask where 1-bits mark the network portion and 0-bits mark the host portion. ANDing the IP with the mask yields the network address.

             Network prefix                Host
IP      : 11000000.10101000.00001010.00011001   = 192.168.10.25
Mask    : 11111111.11111111.11111111.00000000   = 255.255.255.0 (/24)
AND     : 11000000.10101000.00001010.00000000   = 192.168.10.0   ← network address

The /N notation (CIDR) simply counts the number of 1-bits in the mask. /24 means 24 ones followed by 8 zeros, i.e. 255.255.255.0.

4.3 · Three reserved addresses per subnet

AddressHow formedUsage
Network addressAll host bits = 0Identifies the subnet itself. Never assigned to a host.
Broadcast addressAll host bits = 1Sends to every host in this subnet. Never assigned.
Usable host rangeEverything betweenThese are the addresses you can actually assign.

Therefore, the number of usable hosts in a subnet is 2^h − 2, where h is the number of host bits.

4.4 · The two key formulas

Number of subnets       = 2^n        where n = bits borrowed from host portion
Usable hosts per subnet = 2^h − 2    where h = remaining host bits
Block size              = 256 − mask octet value  (in the "interesting" octet)

The "block size" trick is how you subnet quickly without a calculator. If the mask octet is 192, block size = 256 − 192 = 64, so subnets increment by 64 in that octet: .0, .64, .128, .192.

Step-by-step
  1. Determine bits borrowed: new prefix (27) minus original prefix (24) = 3 bits.
  2. Compute number of subnets: 23 = 8.
  3. Compute host bits remaining: 32 − 27 = 5.
  4. Compute usable hosts: 25 − 2 = 30.
  5. Compute block size: 256 − 224 = 32. So subnets increment by 32 in the last octet.
  6. List subnet 0 starting at 0, subnet 1 at 32, subnet 2 at 64, … subnet 7 at 224.
  7. In each subnet: first address = network, first+1 = first usable host, last−1 = last usable host, last = broadcast.
Examiner expects: given any network prefix and a target new prefix (or required number of hosts), you can produce this table cleanly in under 3 minutes. The block-size trick is the shortcut.

4.6 · VLSM — Variable Length Subnet Masking

Classical subnetting splits a network into equally sized subnets. But real networks aren't equal — you might need one subnet with 100 hosts, another with 50, two with 10, and a couple of point-to-point links with 2 hosts each. Using equal subnets wastes huge amounts of address space.

VLSM is the technique of subnetting a subnet — applying different masks to different portions of the same address block so each subnet is exactly the size it needs.

Rule of thumb: always allocate from largest requirement to smallest. Take the biggest subnet first, then the next biggest, and so on. This prevents address fragmentation.

Worked VLSM example

Given block: 192.168.1.0/24
Requirements: A = 100 hosts, B = 50 hosts, C = 20 hosts, D = 2 hosts (P2P)

Step 1: size each subnet (round UP to next power of 2, then add 2 for net+bcast)
  A = 100 → need 7 host bits (2^7−2 = 126 ≥ 100) → /25 → block size 128
  B =  50 → need 6 host bits (2^6−2 =  62 ≥  50) → /26 → block size  64
  C =  20 → need 5 host bits (2^5−2 =  30 ≥  20) → /27 → block size  32
  D =   2 → need 2 host bits (2^2−2 =   2 ≥   2) → /30 → block size   4

Step 2: allocate largest first
  A : 192.168.1.0/25       hosts .1   – .126     bcast .127
  B : 192.168.1.128/26     hosts .129 – .190     bcast .191
  C : 192.168.1.192/27     hosts .193 – .222     bcast .223
  D : 192.168.1.224/30     hosts .225 – .226     bcast .227
  ( 192.168.1.228 – .255 remains free for future use )

Memory aid — "Largest first, block by block." If you allocate smallest first, you end up with a large subnet that no longer fits into a contiguous block and you have to re-do the whole plan.

Walk-through
  1. Host A builds a segment at L4, adds IP header at L3 (source = A, destination = B, TTL = e.g. 64), frames it at L2 (source MAC = A, destination MAC = R1).
  2. R1 receives the frame, discards L2 header, reads IP destination, looks up routing table, finds next hop = R2. Decrements TTL (63), recomputes checksum. Reframes at L2 with source MAC = R1, dest MAC = R2. Forwards.
  3. R2, R3 repeat the same logic — each reframing L2, each touching only TTL at L3.
  4. R4 is the destination's default gateway. It reframes one last time, source MAC = R4, dest MAC = Host B's MAC (from ARP).
  5. Host B receives the frame, strips L2, hands packet up; strips IP header, hands segment up to L4; and the data reaches the correct process.
Examiner expects: you articulate clearly that Layer 2 scope = one hop; Layer 3 scope = end-to-end. Emphasise that the IP packet survives all four routers intact (modulo TTL and checksum), while four different Layer-2 frames came into existence and died during the same journey.

Walk-through
  1. The Transport Layer produces a segment (TCP) or datagram (UDP) — header + application data.
  2. Layer 3 takes the segment as payload and prepends the IP header (H3), which contains source IP, destination IP, TTL, protocol field, checksum, etc.
  3. The result — H3 + segment — is called a packet (or IP datagram).
  4. The packet is handed down to Layer 2, which adds its own header (H2, with MAC addresses) and trailer (T2, with FCS/CRC) to produce a frame.
  5. At the destination, the process reverses — each layer strips its own header before handing up.
Examiner expects: you use the exact terminology. L3 PDU = packet. L4 PDU = segment (TCP) or datagram (UDP). L2 PDU = frame. L1 PDU = bits. Mixing these up loses marks instantly.

Host A ─── Ethernet ───► R1 ─── Fibre ───► R2 ─── Wi-Fi ───► R3 ─── 4G ───► Host B

L2 frames (rebuilt at every hop):
        [Ethernet]     [SONET/PPP]      [802.11]       [LTE]

L3 packet (unchanged end-to-end):
        [ IP header │ payload ]  ───────────────────────────────►

                 "Only TTL and header checksum change."
Walk-through
  1. Host A's IP packet is encapsulated in an Ethernet frame to reach R1.
  2. R1 strips Ethernet, re-encapsulates the same IP packet inside a SONET/PPP frame for the fibre link to R2.
  3. R2 strips PPP, re-encapsulates in 802.11 (Wi-Fi) to R3.
  4. R3 strips 802.11, re-encapsulates in LTE to Host B.
  5. Host B strips LTE — and the IP packet inside is identical to the one Host A sent, minus four TTL decrements.
Examiner expects: "media independence" means the same IP packet traverses different physical technologies without changing. This is what allows the Internet to be a patchwork of Ethernet LANs, fibre backbones, radio links, etc., while behaving as a single logical network.

§ 06 Protocols and Examples

Every Layer-3 protocol Dr. Khan maps in the TCP/IP vs OSI slide (Lec 2 · Slide 42) and Lec 5.

IP (Internet Protocol) — IPv4 / IPv6

The Network Layer's flagship protocol. Provides logical addressing and best-effort, connectionless, media-independent packet delivery.

Real-world usage: every packet on the Internet has an IP header. Your laptop, phone, Wi-Fi router, the server hosting this file — all speak IP. IPv4 = 32-bit addresses; IPv6 = 128-bit addresses, designed to replace IPv4 as address space exhausted.

ICMP (Internet Control Message Protocol)

The "error and diagnostic" protocol that rides on top of IP. Reports unreachable hosts, time-exceeded packets, echo requests/replies.

Real-world usage: ping uses ICMP Echo Request / Echo Reply. traceroute / tracert uses ICMP Time Exceeded messages (sent by each router as TTL expires) to map the path to a destination. When a router drops a packet because the destination is unreachable, it sends back an ICMP Destination Unreachable.

IGMP (Internet Group Management Protocol)

Used by hosts to subscribe to / leave IP multicast groups on the local network.

Real-world usage: IPTV streams to a multicast group; your set-top box sends an IGMP Join to tell its router "send me this stream." When you change channel, it sends IGMP Leave and a Join for the new channel.

ARP (Address Resolution Protocol)

Resolves a known IPv4 address to the corresponding MAC address on the local segment.

Real-world usage: when your laptop wants to send a packet to 192.168.1.1 (the gateway), it broadcasts "Who has 192.168.1.1?" The router replies with its MAC. Your laptop caches the mapping and uses it to build the L2 frame.

Some textbooks place ARP at Layer 2; Dr. Khan's slide 42 and most Cisco material place it at Layer 3 (or "between" L2 and L3). For exam: ARP spans the L2/L3 boundary — it resolves an L3 address into an L2 address.

RARP (Reverse Address Resolution Protocol)

The opposite of ARP — a host that knows its own MAC but not its IP asks the network "who am I?"

Real-world usage: historical, largely replaced by BOOTP and then DHCP. Once used by diskless workstations at boot time.

Routing protocols — RIP, EIGRP, OSPF, BGP

Protocols that run between routers so they can exchange information and build consistent routing tables.

These are covered in depth in Lec 6. At Layer 3, the key point is that routing protocols are not IP itself — they are separate protocols that help IP do its job of forwarding. RIP uses UDP/520, OSPF runs directly over IP (protocol 89), BGP uses TCP/179, EIGRP runs over IP (protocol 88).

Encapsulation & decapsulation role of Layer 3

At the source, Layer 3 receives a segment from Layer 4, wraps it in an IP header (adding source IP, destination IP, TTL, protocol ID), and hands the resulting packet down to Layer 2.

At every intermediate router, Layer 3 is the top of the stack that gets processed. The router does not go up to Layer 4 — it only needs to inspect the IP header to make the forwarding decision. This is what keeps routers fast.

At the destination, Layer 3 strips the IP header and hands the segment up to Layer 4.

The golden rule: routers never look above Layer 3. If your exam scenario says "the router inspected the port number," it's wrong — ports live in the Layer-4 header and are invisible to a pure Layer-3 router. (Stateful firewalls and NAT devices do look at Layer 4, but they're not pure routers.)

§ 08 Must-Remember Points

High-priority facts, exam traps, and memory hooks.

The one-line identity. "The Network Layer is responsible for the delivery of individual packets from the source host to the destination host." — memorise verbatim. It appears in the Review Questions section of Lec 2 and is the classical short answer.

Three duties. Logical addressing, Internetworking, Routing. (Dr. Khan's Slide 34, exact order.)

Four IPv4 adjectives. Connectionless, Best-effort (unreliable), Media-independent, Hierarchical. Know one sentence on each.

Delivery scope mnemonic — "Node, Host, Process." Data Link = node-to-node. Network = host-to-host. Transport = process-to-process. Three words, three layers, in order.

Encapsulation mnemonic — "Data, Segment, Packet, Frame, Bits" — the five PDU names, top-down. Some students prefer "Do Sergeants Pay For Beer?"

Trap: IP addresses vs MAC addresses. Source and destination IP addresses are set by the sender and never change during transit. Source and destination MAC addresses change at every hop. If an exam question asks "what is the source MAC at router 3?" the answer is "router 3's own MAC" — not Host A's MAC.

Trap: TTL. TTL is decremented by every router, not by every device. Switches (L2) do not touch TTL. Hosts receive with TTL > 0; they don't decrement either. Only routers decrement.

Trap: usable hosts. Always subtract 2 (network address and broadcast). A /30 has 22−2 = 2 usable hosts (perfect for point-to-point links), not 4.

Subnetting shortcut — "256 minus the interesting octet." If mask last octet = 192, block size = 64. If = 240, block size = 16. If = 248, block size = 8. Memorise these rather than re-deriving every time.

★★★★★   Maximum — this is the single most exam-heavy layer in the OSI model, by a wide margin.

Why

  • Weight in Lec 5. The entire Lec 5 deck (27 slides) is devoted to just this layer — more than any other. Routing Protocols (Lec 6) is also a direct extension of it.
  • Real-world relevance. "How does the Internet work?" is essentially "How does Layer 3 work?" Every CCNA, every networking job interview, every systems design interview touches Layer 3.
  • Breadth of questions. Routing, subnetting, VLSM, IP addressing, ICMP behaviour, TTL, fragmentation — a single paper can have 3–5 separate questions all at Layer 3.
  • Calculation component. Subnetting is one of the few layers where numerical problems are standard — high-mark, low-ambiguity questions that reward preparation.
