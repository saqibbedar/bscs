Core Concept

Window Functions

The foundation behind ROW_NUMBER, RANK, DENSE_RANK, NTILE, LAG, LEAD, and moving averages. Understand this first and the rest becomes obvious.

What is a Window Function?

Window Function

A function that performs a calculation across a set of rows related to the current row (called the "window"), without collapsing those rows into a single output row. Unlike GROUP BY which collapses rows, window functions return one output row for every input row.

GROUP BY

Collapses multiple rows into one per group. You lose the individual rows. Good for: totals, counts per category.

Window Function

Calculates across a set of rows but keeps every row intact. Good for: rankings, running totals, comparing each row to its group total.

The OVER() Clause — The Key Ingredient

Every window function requires the OVER() clause. This is what makes it a window function:

-- OVER() with nothing = entire result set is the window
ROW_NUMBER() OVER ()

-- OVER(ORDER BY) = rank rows by this column
RANK() OVER (ORDER BY sales DESC)

-- OVER(PARTITION BY) = separate window per group, reset within each group
ROW_NUMBER() OVER (PARTITION BY region)

-- OVER(PARTITION BY ... ORDER BY ...) = rank WITHIN each group
RANK() OVER (PARTITION BY region ORDER BY sales DESC)

-- OVER(ORDER BY ... ROWS ...) = moving window
AVG(SUM(sales)) OVER (ORDER BY month ROWS 2 PRECEDING)

The Three Parts of OVER()

TA Quiz · Most Likely to Appear

ROW_NUMBER()

The function your TA used in the quiz. Assigns a unique sequential integer to each row. Never produces ties — always 1, 2, 3, 4... even when values are equal.

What ROW_NUMBER Does

ROW_NUMBER()

Assigns a unique sequential integer (1, 2, 3...) to each row within the partition defined by OVER(). Even when two rows have identical values, they get different numbers. This makes it useful for pagination, deduplication, and picking one row per group.

Syntax

ROW_NUMBER() OVER (
    [PARTITION BY column]     -- optional: reset numbering within each group
    ORDER BY column [ASC|DESC] -- required: defines the ordering
)

Example 1 — Basic: Rank All Orders by Amount

-- Assign a row number to every order, ordered by total amount descending
SELECT
    order_id,
    buyer_id,
    hut_id,
    total_amount,
    ROW_NUMBER() OVER (
        ORDER BY total_amount DESC
    ) AS row_num
FROM [ORDER]
WHERE status = 'Delivered';

Example 3 — The Classic Use Case: Pick Top 1 Per Group

This is the most common exam question pattern with ROW_NUMBER — get the highest-spending buyer per hut:

-- Step 1: Number buyers within each hut by total spend
WITH ranked_buyers AS (
    SELECT
        o.hut_id,
        o.buyer_id,
        SUM(o.total_amount) AS total_spent,
        ROW_NUMBER() OVER (
            PARTITION BY o.hut_id
            ORDER BY SUM(o.total_amount) DESC
        ) AS rn
    FROM [ORDER] o
    WHERE status = 'Delivered'
    GROUP BY o.hut_id, o.buyer_id
)
-- Step 2: Keep only rank 1 (top buyer per hut)
SELECT rb.hut_id, u.name AS top_buyer, rb.total_spent
FROM ranked_buyers rb
JOIN [USER] u ON rb.buyer_id = u.user_id
WHERE rb.rn = 1
ORDER BY rb.hut_id;

Why ROW_NUMBER is perfect for "top 1 per group"

RANK would fail here if two buyers had equal spend — both would get rank 1 and you'd return two rows for that hut. ROW_NUMBER always picks exactly one, making it reliable for deduplication and "get one per group" queries.

Example 4 — Pagination (OFFSET/FETCH)

Another common use: showing page 2 of results (rows 6-10):

-- T-SQL pagination: skip first 5 rows, take next 5
SELECT order_id, buyer_id, total_amount
FROM [ORDER]
WHERE status = 'Delivered'
ORDER BY total_amount DESC
OFFSET 5 ROWS             -- skip 5 rows
FETCH NEXT 5 ROWS ONLY;  -- take next 5

-- Alternative using ROW_NUMBER in a CTE:
WITH paged AS (
    SELECT order_id, buyer_id, total_amount,
           ROW_NUMBER() OVER (ORDER BY total_amount DESC) AS rn
    FROM [ORDER]
    WHERE status = 'Delivered'
)
SELECT * FROM paged
WHERE rn BETWEEN 6 AND 10;  -- page 2

The critical distinction — memorise this
  • ROW_NUMBER: Always unique. Two tied rows get different numbers. 1, 2, 3, 4, 5. No concept of ties.
  • RANK: Tied rows get the same rank, next rank SKIPS. 1, 2, 2, 4, 5. Gap after ties.
  • DENSE_RANK: Tied rows get the same rank, next rank does NOT skip. 1, 2, 2, 3, 4. No gaps.

RANK() and DENSE_RANK()

Directly from Chapter 33 of Connolly & Begg. Your book uses the Edinburgh branch example — here adapted to your QHUTS huts.

Definition and Syntax

Ranking Functions

Compute the rank of a record compared to other records in the dataset based on the values of a set of measures. RANK() leaves gaps in the ranking sequence when there are ties. DENSE_RANK() does not leave gaps.

-- Exact syntax from Connolly & Begg Ch 33:
RANK()       OVER (ORDER BY columnList)
DENSE_RANK() OVER (ORDER BY columnList)

-- Can also partition within groups:
RANK()       OVER (PARTITION BY col ORDER BY measure DESC)
DENSE_RANK() OVER (PARTITION BY col ORDER BY measure DESC)

Book Example — Adapted to Your Project

The book (Ch 33, Example 33.3) uses Edinburgh branch offices. Here is the exact same pattern applied to your QHUTS huts:

-- Book Example 33.3 adapted: rank huts by total sales revenue
SELECT
    h.hut_id,
    h.name AS hut_name,
    SUM(o.total_amount) AS sales,
    RANK()       OVER (ORDER BY SUM(o.total_amount) DESC) AS ranking,
    DENSE_RANK() OVER (ORDER BY SUM(o.total_amount) DESC) AS dense_ranking
FROM [ORDER] o
JOIN HUT h ON o.hut_id = h.hut_id
WHERE o.status = 'Delivered'
GROUP BY h.hut_id, h.name;

Finding Top N per Group Using RANK

-- Top 2 products per category by revenue
WITH product_ranks AS (
    SELECT
        c.category_name,
        p.item_name,
        SUM(oi.quantity * oi.unit_price) AS revenue,
        DENSE_RANK() OVER (
            PARTITION BY c.category_name
            ORDER BY SUM(oi.quantity * oi.unit_price) DESC
        ) AS dr
    FROM ORDER_ITEM oi
    JOIN PRODUCT p ON oi.product_id = p.product_id
    JOIN CATEGORY c ON p.cat_id = c.cat_id
    GROUP BY c.category_name, p.item_name
)
SELECT category_name, item_name, revenue, dr
FROM product_ranks
WHERE dr <= 2    -- top 2 per category
ORDER BY category_name, dr;

GROUP BY ROLLUP

Your exact lab SQL. Hierarchical subtotals. Country → Region → City. The n+1 formula. What NULL means in every row.

What ROLLUP Does

ROLLUP Extension to GROUP BY

Creates subtotals that roll up from the most detailed level to a grand total, following the column list specified. ROLLUP creates subtotals at n+1 levels where n is the number of grouping columns. (From Connolly & Begg Ch 33.)

Your Exact Lab Query

USE SalesDB;

SELECT
    Country,
    Region,
    City,
    SUM(Sales_Amount) AS Total_Sales,
    SUM(Quantity)     AS Total_Quantity
FROM dbo.sales_dataset
GROUP BY ROLLUP (Country, Region, City)
ORDER BY Country, Region, City;
What ROLLUP(Country, Region, City) produces — n=3, so n+1=4 levels
  • Level 1: GROUP BY Country + Region + City → full detail (each city row)
  • Level 2: GROUP BY Country + Region → subtotal across all cities per region (City becomes NULL)
  • Level 3: GROUP BY Country → subtotal across all regions (Region AND City become NULL)
  • Level 4: GROUP BY nothing → grand total (all three columns are NULL)

The NULL Rule — He Will Ask This
  • NULL in City only → subtotal across all cities within that Region
  • NULL in City + Region → subtotal across all regions within that Country
  • NULL in all three columns → GRAND TOTAL (entire table)
  • ROLLUP drops columns from the RIGHT side first at each level
  • Since all rows are Pakistan, Level 3 and Level 4 show the same number — in a real multi-country dataset they would differ

Making ROLLUP Output Readable — COALESCE

-- Replace NULLs with meaningful labels
SELECT
    COALESCE(Country, 'ALL COUNTRIES') AS Country,
    COALESCE(Region,  'ALL REGIONS')   AS Region,
    COALESCE(City,    'ALL CITIES')    AS City,
    SUM(Sales_Amount)                   AS Total_Sales
FROM dbo.sales_dataset
GROUP BY ROLLUP (Country, Region, City);

-- Now subtotal rows show "ALL REGIONS" instead of NULL

ROLLUP on Your QHUTS Project Data

-- Monthly revenue rollup: Hut → Category → Month
SELECT
    h.name          AS hut_name,
    c.category_name,
    t.month_name,
    SUM(f.total_revenue) AS revenue
FROM QHUTS_DataWarehouse.dbo.DM1_FACT_ORDER_SALES f
JOIN QHUTS_DataWarehouse.dbo.DIM_TIME          t ON f.time_key      = t.time_key

JOIN QHUTS_DataWarehouse.dbo.DM1_DIM_CATEGORY  c ON f.category_key  = c.category_key
GROUP BY ROLLUP (h.name, c.category_name, t.month_name)
ORDER BY h.name, c.category_name, t.month_name;

-- n=3 → 4 levels:
-- Level 1: per hut + category + month
-- Level 2: per hut + category (all months)  
-- Level 3: per hut (all categories + months)
-- Level 4: grand total

The Formula

ROLLUP(A, B, C)  →  n = 3  →  n+1 = 4 levels
ROLLUP(A, B)     →  n = 2  →  n+1 = 3 levels
ROLLUP(A)        →  n = 1  →  n+1 = 2 levels

Levels drop columns RIGHT-TO-LEFT:
(A, B, C)   → detail
(A, B)      → subtotal, C is NULL
(A)         → subtotal, B and C are NULL
()          → grand total, all NULL

Your exact lab SQL. All 2ⁿ combinations. Cross-dimensional subtotals that ROLLUP cannot produce. Full annotated output.

What CUBE Does

CUBE Extension to GROUP BY

Takes a set of grouping columns and creates subtotals for ALL possible combinations. If n columns are specified, CUBE produces 2ⁿ combinations of subtotals. (From Connolly & Begg Ch 33.) CUBE is typically most suitable for queries involving columns from multiple independent dimensions.

Your Exact Lab Query

USE SalesDB;

SELECT
    Product_Category,
    Region,
    YEAR(Date) AS Year,
    SUM(Sales_Amount) AS Total_Sales,
    SUM(Quantity)     AS Total_Quantity
FROM dbo.sales_dataset
GROUP BY CUBE (Product_Category, Region, YEAR(Date));

CUBE on Your QHUTS Data

-- CUBE analysis on DM2: product performance across all dimensions
SELECT
    COALESCE(p.category,    'ALL CATEGORIES') AS Category,
    COALESCE(h.hut_name,    'ALL HUTS')       AS Hut,
    COALESCE(CAST(t.month_num AS VARCHAR), 'ALL MONTHS') AS Month,
    SUM(f.qty_sold)  AS total_qty,

FROM DM2_FACT_PRODUCT_PERFORMANCE f

JOIN DM2_DIM_HUT     h  ON f.hut_key     = h.hut_key
JOIN DIM_TIME        t  ON f.time_key    = t.time_key
GROUP BY CUBE (p.category, h.hut_name, t.month_num)
ORDER BY Category, Hut, Month;

ROLLUP vs CUBE — The Formula

ROLLUP(A, B, C)  →  n = 3  →  n+1 = 4 levels  (hierarchical)
CUBE(A, B, C)    →  n = 3  →  2³  = 8 combos  (all combinations)

CUBE always produces MORE rows than ROLLUP for the same columns.

USE ROLLUP when: natural hierarchy exists (Country→Region→City)
USE CUBE when:   dimensions are independent (Category × Region × Year)

CASE WHEN — Basic Syntax

CASE WHEN

SQL's conditional expression. Evaluates conditions in order, returns the first matching result. Like an if-else chain inside a SQL expression. Works in SELECT, WHERE, ORDER BY, GROUP BY, and inside aggregate functions.

-- Simple CASE (compare one value)
CASE column_name
    WHEN value1 THEN result1
    WHEN value2 THEN result2
    ELSE default_result
END

-- Searched CASE (any condition)
CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
    ELSE default_result
END

Conditional Aggregation — The Pattern Khalid Tests

This is the most important pattern from your project. SUM with CASE WHEN inside it — count or sum only rows meeting a condition:

-- From your QHUTS DM4 (Feedback fact table population):
SELECT
    COUNT(f.feedback_id)                             AS num_feedbacks,
    AVG(CAST(f.rating AS DECIMAL(4,2)))              AS avg_rating,

    -- Count only 5-star ratings:
    SUM(CASE WHEN f.rating = 5 THEN 1 ELSE 0 END)   AS five_star_count,

    -- Count only 4-star ratings:
    SUM(CASE WHEN f.rating = 4 THEN 1 ELSE 0 END)   AS four_star_count,

    -- Count only 3-star ratings:
    SUM(CASE WHEN f.rating = 3 THEN 1 ELSE 0 END)   AS three_star_count,

    -- Count 1 or 2 star (low ratings):
    SUM(CASE WHEN f.rating <= 2 THEN 1 ELSE 0 END)  AS low_rating_count

FROM FEEDBACK f;

-- Pattern: SUM(CASE WHEN condition THEN 1 ELSE 0 END) = conditional COUNT
-- Pattern: SUM(CASE WHEN condition THEN value ELSE 0 END) = conditional SUM

Conditional Aggregation — DM5 (Cancellation Rate)

From your actual DM5 fact table population in QHUTS_DataMarts.sql:

-- From your project — EXACTLY as written in QHUTS_DataMarts.sql:
SELECT
    COUNT(o.order_id)                                               AS total_orders,
    SUM(CASE WHEN o.status = 'Delivered'  THEN 1 ELSE 0 END)     AS delivered_orders,
    SUM(CASE WHEN o.status = 'Cancelled'  THEN 1 ELSE 0 END)     AS cancelled_orders,
    SUM(CASE WHEN o.status IN ('Pending','Preparing','OutForDelivery')
             THEN 1 ELSE 0 END)                                    AS pending_orders,
    CAST(
        100.0 * SUM(CASE WHEN o.status = 'Cancelled' THEN 1 ELSE 0 END)
        / NULLIF(COUNT(o.order_id), 0)
    AS DECIMAL(5,2))                                                 AS cancellation_rate
FROM [ORDER] o;

NULLIF — Preventing Division by Zero

NULLIF(expr1, expr2)

Returns NULL if expr1 = expr2, otherwise returns expr1. The classic use is preventing division by zero: if the denominator is 0, return NULL instead of crashing.

-- Without NULLIF: if COUNT = 0, this CRASHES with division by zero error
100.0 * cancelled / COUNT(order_id)

-- With NULLIF: if COUNT = 0, NULLIF returns NULL, and NULL/anything = NULL (safe)
100.0 * cancelled / NULLIF(COUNT(order_id), 0)

-- General pattern:
numerator / NULLIF(denominator, 0)

COALESCE — Handle NULLs Elegantly

COALESCE(val1, val2, val3...)

Returns the first non-NULL value from its argument list. More flexible than ISNULL (which only takes 2 arguments).

-- Replace NULL with a default
COALESCE(cancellation_reason, 'No reason given')

-- Replace NULLs in ROLLUP output
COALESCE(Region, 'ALL REGIONS')

-- Use first non-null of multiple columns
COALESCE(actual_delivery_time, estimated_delivery_time, order_time)

CAST — Type Conversion

CAST(expression AS datatype)

Converts a value from one data type to another. Common uses: converting INT to DECIMAL for division precision, converting DATE to VARCHAR for display.

-- Used in your DM4 — convert INT rating to DECIMAL for AVG precision:
AVG(CAST(f.rating AS DECIMAL(4,2)))

-- Used in your DM5 — ensure percentage is decimal not integer division:
CAST(100.0 * cancelled / total AS DECIMAL(5,2))

-- Used in DM1 — convert DATETIME to DATE for joining to DIM_TIME:
CAST(o.order_time AS DATE) = dt.full_date

-- T-SQL alternative: CONVERT(DECIMAL(5,2), expression)

DATEDIFF — Date Arithmetic

DATEDIFF(unit, start, end)

Returns the number of specified units (MINUTE, HOUR, DAY, MONTH, YEAR) between two dates. Used in your DM5 to calculate delivery time in minutes.

-- From your DM5 — calculate average delivery time in minutes:

         THEN DATEDIFF(MINUTE, o.order_time, o.actual_delivery_time)
         ELSE NULL
    END) AS avg_delivery_mins

-- Other units:
DATEDIFF(DAY,   start_date, end_date)   -- number of days
DATEDIFF(MONTH, start_date, end_date)   -- number of months
DATEDIFF(YEAR,  start_date, end_date)   -- number of years

-- MySQL equivalent (different syntax):
-- TIMESTAMPDIFF(MINUTE, start, end)
-- DATEDIFF(end, start)  -- MySQL only gives days

IIF — Shorthand CASE WHEN

-- IIF(condition, true_value, false_value) = simplified CASE WHEN
IIF(rating >= 4, 'Good', 'Poor')

-- Equivalent CASE WHEN:

-- Note: IIF is T-SQL specific. Standard SQL uses CASE WHEN.

and Derived Tables

Common Table Expressions (WITH...AS), correlated subqueries, and derived tables. How to write multi-step analytical queries cleanly. Your project used CTEs for window function queries.

What is a CTE?

Common Table Expression (CTE)

A named temporary result set defined within a WITH clause that you can reference in the subsequent SELECT, INSERT, UPDATE, or DELETE statement. Think of it as a "named subquery" — it runs once and can be referenced multiple times. Syntax: WITH name AS (query) SELECT ... FROM name

Syntax

-- Single CTE
WITH cte_name AS (
    SELECT ...
    FROM ...
    WHERE ...
)
SELECT * FROM cte_name;

-- Multiple CTEs (chain them with commas)
WITH
    cte1 AS (
        SELECT ... FROM ...
    ),
    cte2 AS (
        SELECT ... FROM cte1   -- cte2 can reference cte1
    )
SELECT * FROM cte2;

CTE vs Subquery vs Derived Table

ApproachSyntaxReadabilityReusable?
SubqueryNested inside another query with ()Poor for complex logicNo — write it again
Derived TableSubquery in FROM clause with aliasMediumNo — write it again
CTEWITH name AS (...) before main queryBest — reads top to bottomYes — reference by name

Example 1 — Same Query Three Ways

Goal: Find buyers who spent more than the average order amount on their orders:

Method 1: Subquery (nested)
SELECT buyer_id, SUM(total_amount) AS total_spent
FROM [ORDER]
WHERE status = 'Delivered'
GROUP BY buyer_id
HAVING SUM(total_amount) > (
    SELECT AVG(total_amount)
    FROM [ORDER]
    WHERE status = 'Delivered'
);
Method 2: Derived Table
SELECT buyer_id, total_spent
FROM (
    SELECT buyer_id, SUM(total_amount) AS total_spent
    FROM [ORDER]
    WHERE status = 'Delivered'
    GROUP BY buyer_id
) buyer_totals
WHERE total_spent > (
    SELECT AVG(total_amount) FROM [ORDER] WHERE status = 'Delivered'
);
Method 3: CTE (cleanest)
WITH
    buyer_totals AS (
        SELECT buyer_id, SUM(total_amount) AS total_spent
        FROM [ORDER]
        WHERE status = 'Delivered'
        GROUP BY buyer_id
    ),
    avg_spend AS (
        SELECT AVG(total_amount) AS avg_order
        FROM [ORDER]
        WHERE status = 'Delivered'
    )
SELECT bt.buyer_id, u.name, bt.total_spent
FROM buyer_totals bt
JOIN avg_spend a ON bt.total_spent > a.avg_order
JOIN [USER] u   ON bt.buyer_id = u.user_id
ORDER BY bt.total_spent DESC;

CTE + Window Function — The Classic Combo

You MUST use a CTE (or subquery) to filter on window function results. You cannot use WHERE on a window function in the same query level:

-- WRONG: you cannot filter on ROW_NUMBER in the same SELECT
SELECT hut_id, buyer_id, total_amount,
       ROW_NUMBER() OVER (...) AS rn
FROM [ORDER]
WHERE rn = 1;  -- ❌ ERROR: rn not available in WHERE

-- CORRECT: compute in CTE, then filter in outer query
WITH ranked AS (
    SELECT hut_id, buyer_id, total_amount,
           ROW_NUMBER() OVER (PARTITION BY hut_id ORDER BY total_amount DESC) AS rn
    FROM [ORDER]
    WHERE status = 'Delivered'
)
SELECT hut_id, buyer_id, total_amount
FROM ranked
WHERE rn = 1;  -- ✅ Works — we're filtering from the CTE
Rule: Window functions in WHERE → always use CTE or subquery

You cannot reference a window function alias (rn, row_num, ranking) in a WHERE or HAVING clause in the same query level. Always wrap it in a CTE or subquery first, then filter in the outer query.

Correlated Subquery — Advanced Pattern

A subquery that references columns from the outer query. Runs once per row of the outer query:

-- For each hut, show its name and whether its revenue is above average
SELECT
    h.name AS hut_name,
    SUM(o.total_amount) AS revenue,
    CASE WHEN
        SUM(o.total_amount) > (
            SELECT AVG(sub_total)
            FROM (
                SELECT SUM(total_amount) AS sub_total
                FROM [ORDER]
                WHERE status = 'Delivered'
                GROUP BY hut_id
            ) avg_calc
        )
    THEN 'Above Average'
    ELSE 'Below Average'
    END AS performance
FROM [ORDER] o
JOIN HUT h ON o.hut_id = h.hut_id
WHERE o.status = 'Delivered'
GROUP BY h.hut_id, h.name;

LAG and LEAD — Compare Rows

-- LAG: access value from a PREVIOUS row
-- LEAD: access value from a NEXT row

SELECT
    t.month_name,
    SUM(f.total_revenue) AS this_month,

    -- Previous month revenue (1 row back)
    LAG(SUM(f.total_revenue), 1, 0) OVER (
        ORDER BY t.month_num
    ) AS prev_month,

    -- Month-over-month change
    SUM(f.total_revenue) - LAG(SUM(f.total_revenue), 1, 0) OVER (
        ORDER BY t.month_num
    ) AS month_change,

    -- Next month revenue (1 row ahead)
    LEAD(SUM(f.total_revenue), 1, 0) OVER (
        ORDER BY t.month_num
    ) AS next_month

FROM DM1_FACT_ORDER_SALES f
JOIN DIM_TIME t ON f.time_key = t.time_key
GROUP BY t.month_num, t.month_name
ORDER BY t.month_num;

-- Syntax: LAG(column, offset, default_if_null)
-- offset: how many rows back (default 1)
-- default: what to return if no row exists at that offset

Pattern 1 — WHILE Loop for DIM_TIME Population

-- Populate all dates Jan–Aug 2024 without manually inserting 244 rows
DECLARE @d DATE = '2024-01-01';
WHILE @d <= '2024-08-31'
BEGIN
    INSERT INTO DIM_TIME (full_date, day_of_week, day_num, week_num,
                           month_num, month_name, quarter, year_num, is_weekend)
    VALUES (
        @d,
        DATENAME(WEEKDAY, @d),          -- 'Monday', 'Tuesday'...
        DAY(@d),                         -- day number in month (1-31)
        DATEPART(WEEK, @d),              -- week number in year (1-52)
        MONTH(@d),                       -- month number (1-12)
        DATENAME(MONTH, @d),             -- 'January', 'February'...
        DATEPART(QUARTER, @d),           -- quarter (1-4)
        YEAR(@d),                        -- year (2024)
        CASE WHEN DATEPART(WEEKDAY, @d) IN (1,7)
             THEN 1 ELSE 0 END          -- is_weekend: 1=Sat/Sun, 0=weekday
    );
    SET @d = DATEADD(DAY, 1, @d);       -- advance by 1 day
END
What this demonstrates
  • DECLARE — T-SQL variable declaration (@variable_name syntax)
  • WHILE loop — procedural programming in SQL
  • DATENAME — returns named part of a date as string
  • DATEPART — returns numeric part of a date
  • DATEADD — add a number of units to a date
  • CASE WHEN inside INSERT VALUES — conditional value at insert time

Pattern 3 — Complex Conditional Aggregation (DM5)

-- DM5: Operational metrics with 5 different CASE WHEN patterns
SELECT
    dt.time_key,
    dh.hut_key,

    COUNT(o.order_id)                                           AS total_orders,

    SUM(CASE WHEN o.status = 'Delivered'  THEN 1 ELSE 0 END)  AS delivered_orders,
    SUM(CASE WHEN o.status = 'Cancelled'  THEN 1 ELSE 0 END)  AS cancelled_orders,
    SUM(CASE WHEN o.status IN
            ('Pending','Preparing','OutForDelivery')
             THEN 1 ELSE 0 END)                                 AS pending_orders,

    -- Cancellation rate = cancelled / total * 100
    -- NULLIF prevents division by zero
    -- CAST ensures decimal output (not integer division)
    CAST(
        100.0 * SUM(CASE WHEN o.status = 'Cancelled' THEN 1 ELSE 0 END)
        / NULLIF(COUNT(o.order_id), 0)
    AS DECIMAL(5,2))                                             AS cancellation_rate,

    -- Average delivery time in minutes — NULL-safe (skips orders without delivery time)
    AVG(CASE WHEN o.actual_delivery_time IS NOT NULL
             THEN DATEDIFF(MINUTE, o.order_time, o.actual_delivery_time)
             ELSE NULL
        END)                                                        AS avg_delivery_mins,

    -- Total revenue only from delivered orders
    SUM(CASE WHEN o.status = 'Delivered'
             THEN o.total_amount ELSE 0
        END)                                                        AS total_revenue

FROM QHUTS_OLTP.dbo.[ORDER] o
JOIN DIM_TIME    dt ON CAST(o.order_time AS DATE) = dt.full_date
JOIN DM5_DIM_HUT dh ON o.hut_id = dh.hut_id
GROUP BY dt.time_key, dh.hut_key;

Window Functions

Window🔥 TA QuizWhat is ROW_NUMBER()? Write a query that assigns a row number to each hut's orders ordered by amount.

ROW_NUMBER() assigns a unique sequential integer to each row within the window defined by OVER(). It never produces ties — even if two rows have equal values, they get different numbers.

SELECT order_id, hut_id, total_amount,
       ROW_NUMBER() OVER (
           PARTITION BY hut_id
           ORDER BY total_amount DESC
       ) AS rn
FROM [ORDER]
WHERE status = 'Delivered';

PARTITION BY hut_id means the row number resets for each hut (1, 2, 3 per hut, not globally).

Window🔥 HotHow do you get the top 1 order per hut using ROW_NUMBER? Why not use MAX()? 
WITH ranked AS (
    SELECT order_id, hut_id, total_amount,
           ROW_NUMBER() OVER (PARTITION BY hut_id ORDER BY total_amount DESC) AS rn
    FROM [ORDER]
    WHERE status = 'Delivered'
)
SELECT hut_id, order_id, total_amount
FROM ranked
WHERE rn = 1;

MAX() gives you the maximum value but not the other columns for that row (you can't know which order_id had the max amount). ROW_NUMBER lets you filter to the specific row with the highest amount and retrieve all its columns.

WindowWhy can't you write WHERE ROW_NUMBER() = 1 directly in the same SELECT?

Window functions are evaluated after the WHERE clause but before the final SELECT. So when WHERE is processed, the row_num alias doesn't exist yet. You must wrap the window function in a CTE or subquery, then filter in the outer query:

WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY hut_id ORDER BY amount DESC) AS rn
    FROM [ORDER]
)
SELECT * FROM ranked WHERE rn = 1;  -- filter in outer query ✅

RANK and DENSE_RANK

Rank🔥 Book Ch33What is the difference between RANK() and DENSE_RANK()? Give an example with ties.
  • RANK(): Assigns the same rank to tied rows, but leaves gaps. If three rows tie for 2nd, the next rank is 5th (2nd, 2nd, 2nd, 5th). Gap = number of tied rows.
  • DENSE_RANK(): Assigns the same rank to tied rows, NO gaps. If three rows tie for 2nd, the next rank is 3rd (2nd, 2nd, 2nd, 3rd).
SELECT hut_name, total_revenue,
       RANK()       OVER (ORDER BY total_revenue DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY total_revenue DESC) AS d_rnk
FROM (
    SELECT h.name AS hut_name, SUM(o.total_amount) AS total_revenue
    FROM [ORDER] o JOIN HUT h ON o.hut_id = h.hut_id
    WHERE o.status = 'Delivered'
    GROUP BY h.name
) hut_totals;

If Main Gate and Hostel Block 3 both have revenue 1,000: both get rank 2. RANK gives Sports Complex rank 4. DENSE_RANK gives it rank 3.

RankWrite a query to find the top 2 products per category by revenue. 
WITH product_ranks AS (
    SELECT c.category_name, p.item_name,
           SUM(oi.quantity * oi.unit_price) AS revenue,
           DENSE_RANK() OVER (
               PARTITION BY c.category_name
               ORDER BY SUM(oi.quantity * oi.unit_price) DESC
           ) AS dr
    FROM ORDER_ITEM oi
    JOIN PRODUCT p ON oi.product_id = p.product_id
    JOIN CATEGORY c ON p.cat_id = c.cat_id
    GROUP BY c.category_name, p.item_name
)
SELECT category_name, item_name, revenue, dr
FROM product_ranks
WHERE dr <= 2
ORDER BY category_name, dr;

ROLLUP

ROLLUP🔥 Lab + BookWrite the ROLLUP query from your lab. What does NULL mean in the output? 
USE SalesDB;
SELECT
    Country, Region, City,
    SUM(Sales_Amount) AS Total_Sales,
    SUM(Quantity)     AS Total_Quantity
FROM dbo.sales_dataset
GROUP BY ROLLUP (Country, Region, City)
ORDER BY Country, Region, City;

With n=3 columns, ROLLUP produces n+1 = 4 levels:

  • NULL in City only → subtotal for that Region (all cities in that region)
  • NULL in City + Region → subtotal for that Country (all regions)
  • NULL in all three columns → grand total (entire table)

ROLLUP drops columns from RIGHT to LEFT at each level.

ROLLUPWhat is the formula for how many rows ROLLUP and CUBE produce?
  • ROLLUP(A, B, C): n = 3 columns → n+1 = 4 aggregation levels
  • CUBE(A, B, C): n = 3 columns → 2³ = 8 combinations

CUBE always produces more rows than ROLLUP with the same columns. ROLLUP is hierarchical (drops columns right-to-left). CUBE generates every possible combination.

CUBE

CUBE🔥 Lab + BookWrite the CUBE query from your lab. What combinations does it generate that ROLLUP does not? 
USE SalesDB;
SELECT
    Product_Category,
    Region,
    YEAR(Date) AS Year,
    SUM(Sales_Amount) AS Total_Sales,
    SUM(Quantity)     AS Total_Quantity
FROM dbo.sales_dataset
GROUP BY CUBE (Product_Category, Region, YEAR(Date));

n=3 → 2³ = 8 combinations. CUBE includes everything ROLLUP would produce PLUS:

  • (Region, Year) — region + year totals, across all categories
  • (Region) — region-only totals, across all categories and years
  • (Year) — year-only totals, across all categories and regions

These cross-dimensional subtotals are what CUBE adds that ROLLUP can't produce.

CASE WHEN

CASE🔥 Project PatternWrite a query that counts how many orders for each hut were Delivered, Cancelled, and Pending. 
SELECT
    h.name AS hut_name,
    COUNT(o.order_id) AS total_orders,
    SUM(CASE WHEN o.status = 'Delivered'  THEN 1 ELSE 0 END) AS delivered,
    SUM(CASE WHEN o.status = 'Cancelled'  THEN 1 ELSE 0 END) AS cancelled,
    SUM(CASE WHEN o.status IN ('Pending','Preparing','OutForDelivery')
             THEN 1 ELSE 0 END) AS pending,
    CAST(
        100.0 * SUM(CASE WHEN o.status = 'Cancelled' THEN 1 ELSE 0 END)
        / NULLIF(COUNT(o.order_id), 0)
    AS DECIMAL(5,2)) AS cancel_pct
FROM [ORDER] o
JOIN HUT h ON o.hut_id = h.hut_id
GROUP BY h.hut_id, h.name
ORDER BY total_orders DESC;
CASEWhat does NULLIF do? Why is it used in cancellation rate calculations?

NULLIF(expr1, expr2) returns NULL if expr1 = expr2, otherwise returns expr1. In cancellation rate: if a hut has 0 orders, dividing by zero would cause a runtime error. NULLIF(COUNT(order_id), 0) returns NULL when count = 0, and NULL/anything = NULL (safe, no crash).

-- Without NULLIF: error if count = 0
100.0 * cancelled / COUNT(order_id)

-- With NULLIF: returns NULL instead of dividing by zero
100.0 * cancelled / NULLIF(COUNT(order_id), 0)

CTEs

CTEWhat is a CTE? Write a CTE that finds huts where average delivery time exceeds 20 minutes.

A Common Table Expression is a named temporary result set defined with WITH...AS before the main query. It improves readability and can be referenced multiple times.

WITH hut_delivery AS (
    SELECT
        h.name AS hut_name,
        AVG(CASE WHEN o.actual_delivery_time IS NOT NULL
                 THEN DATEDIFF(MINUTE, o.order_time, o.actual_delivery_time)
                 ELSE NULL END) AS avg_delivery_mins,
        COUNT(o.order_id) AS total_orders
    FROM [ORDER] o
    JOIN HUT h ON o.hut_id = h.hut_id
    WHERE o.status = 'Delivered'
    GROUP BY h.hut_id, h.name
)
SELECT hut_name, avg_delivery_mins, total_orders
FROM hut_delivery
WHERE avg_delivery_mins > 20
ORDER BY avg_delivery_mins DESC;
